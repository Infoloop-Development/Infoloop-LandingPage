# SEO, OG image, and LLM summaries

**Audience:** Infoloop marketing / ops  
**Where:** CMS page forms → **SEO & social**  
**Live file for AI crawlers:** `/llms.txt`

---

## What we have today

| Field | What it controls |
| --- | --- |
| **Meta title** | `<title>` and `og:title` / Twitter title |
| **Meta description** | Meta description and `og:description` |
| **OG / social image** | Per-page `og:image` and Twitter image (else site default `/og.png`) |
| **LLM / answer-engine summary** | Optional blurb appended under “Page summaries” in `/llms.txt` |
| **Hide from search (noindex)** | Robots noindex when ticked |

H1 on the page is separate from meta title.

There are **no** separate OG title / OG description fields — they always match meta title / description.

---

## How to use (no developer)

1. Open the page in CMS (service, product, case study, hire, industry, solutions, about, etc.).
2. Find **SEO & social**.
3. Set meta title (≤ 60 chars) and description (≈ 110–158).
4. Optional: upload a **1200×630** social image.
5. Optional: write a short **LLM summary** (one or two plain sentences).
6. Save and wait for the site rebuild (deploy hook).

Then check:

- Page source / social debugger for OG tags  
- `https://<your-site>/llms.txt` for appended page summaries  

---

## Impact

- Share previews can be unique per page instead of one global Infoloop image.  
- Search snippets stay editable from the CMS.  
- Answer engines get optional extra blurbs without editing the handbook by hand.  
- Saving SEO triggers the same rebuild as other CMS publishes.

---

## Technical notes (engineering)

- Shared field: `cms/src/fields/index.ts` → `seo`  
- Layout: `web/src/layouts/Base.astro` accepts `image`  
- Flatten uploads: `web/src/lib/seo.ts` + `web/src/lib/cms.ts`  
- `/llms.txt`: generated by `web/src/pages/llms.txt.ts` from `web/src/content/llms-base.txt` + CMS `llmSummary` values
